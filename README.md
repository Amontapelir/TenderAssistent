# TenderAssistant

Помощник по выбору государственных закупок для компании-исполнителя. По каждой закупке он собирает
карточку: подходит ли она компании, кто выигрывал у этого заказчика раньше, какие требования
стоят в документации, какой цены ждать и на что обратить внимание. У каждого вывода есть
источник, у каждого требования из документации есть дословная цитата.

Примером служит ПАО «ВымпелКом» (Билайн): профиль построен по его контрактам из открытого
реестра. Проект учебный, сделан по собственной инициативе и работает только с публичными данными.

**Посмотреть результат без установки:** https://amontapelir.github.io/TenderAssistent/

На странице три разобранные закупки с требованиями и цитатами, проверка правил на прошлых
закупках, список закупок по запросу и профиль компании. Это готовые файлы, собранные программой:
поиск и новый анализ на странице не запускаются.

## Зачем

Закупок по одной только связи публикуются десятки в неделю, а документация одной закупки
занимает от 50 до 250 тысяч знаков. Прочитать всё нельзя, а пропущенное требование (опыт
на 20% начальной цены, обеспечение в 30%) стоит дорого. Помощник не решает за человека, участвовать
ли в закупке. Он сокращает путь до решения и показывает, на чём основан каждый вывод.

## Как это работает

1. **Профиль компании.** Из реестра берутся контракты компании как поставщика: коды ОКПД2,
   заказчики, регионы, размер контрактов, снижение цены на торгах.
2. **Подборка и кандидаты.** Программа сама ищет открытые закупки по самым частым словам из названий
   контрактов компании, ставит каждой балл (сходство названия с контрактами компании, опыт у заказчика,
   размер) и оставляет двадцать лучших. Закупку по номеру или из списка можно разобрать подробно.
   Поиск по своему запросу тоже есть.
3. **История заказчика.** Его прошлые контракты: какие похожи на закупку, кто их выиграл,
   насколько снижалась цена.
4. **Чтение документации.** Файлы закупки скачиваются с zakupki.gov.ru, делятся на части и
   читаются языковой моделью. Модель выписывает требования к участнику и рискованные условия
   и к каждому приводит цитату.
5. **Проверка цитат.** Программа ищет каждую цитату в тексте документа. Вывод без найденной
   цитаты в карточку не попадает; он остаётся в отдельном списке отброшенных с причиной.
6. **Оценка.** Ожидаемая цена считается по снижению в прошлых закупках заказчика. Шансы
   оцениваются правилами: сумма названных факторов, диапазон вместо одного числа.
7. **Карточка.** Один файл JSON со всеми блоками, источниками и перечнем того, что не удалось
   проверить.

## Ключевые решения

- **Модель читает, считает программа.** Цены, снижение, шансы и совпадение области считает
  обычный код на стандартной библиотеке Python. Модель только извлекает текст из документов,
  оценивает важность требований и предлагает гипотезы.
- **Нет цитаты, нет вывода.** Пересказ без дословной опоры в документе отбрасывается.
- **Оценка не знает исхода.** Контракт самой закупки исключается из данных; для завершённой
  закупки используется только то, что было опубликовано до её объявления.
- **«Неизвестно» остаётся неизвестным.** Есть ли у компании лицензии, персонал и оборудование,
  по открытым данным не видно. Такие требования помечаются для проверки внутри компании и
  на оценку шансов не влияют.
- **Каждое ограничение названо.** Если что-то обрезано, пропущено или не прочитано, об этом
  сказано в самом файле результата.
- **Данные из документов не команды.** Текст документации передаётся модели как материал для
  анализа; указания внутри него не выполняются.

## Что измерено

Данные на 14.11.2026, компания: ПАО «ВымпелКом».

**Проверка правил на прошлых закупках.** 203 закупки, которые компания выиграла, сравнивались
с 529 закупками тех же десяти заказчиков, которые выиграл кто-то другой. Каждая оценивалась
только по данным, известным до неё. Чисел два, потому что одно из них вводит в заблуждение:

| Показатель | Значение |
|---|---|
| Выигранная закупка оценена выше чужой, **среди закупок, похожих на дело компании** | в 21% пар (интервал 10–34%; 19 побед и 50 чужих у 5 заказчиков) |
| То же, по всем закупкам | в 74% пар (интервал 65–84%) |
| Выигранные закупки с оценкой «низкий» | 23 из 203 (11%) |

50% значило бы, что правила не различают исход. **Среди похожих закупок они на этих данных хуже
случайного**, то есть проверку сегодняшние правила не проходят. Число по всем закупкам выше, потому что
чужие закупки заказчиков в основном вообще не из области компании: оно отвечает на вопрос «похоже ли
это на дело компании», а не «выиграет ли она». Каждый фактор проверяется отдельно: область по кодам и
сходство названия различают «своё» и «чужое», а факторы «побеждала у заказчика» и «цена не снижалась»
среди похожих закупок указывают в обратную сторону. Это в первую очередь следствие состава выборки
(заказчики выбраны по числу побед компании, победы идут сериями у немногих заказчиков), а не
доказательство, что факторы неверны: проверить и откалибровать их по такой выборке нельзя.
Веса правил поэтому **не менялись**: подгонка под 19 побед у 5 заказчиков и под сегодняшний открытый
профиль была бы подгонкой, и устарела бы, когда в профиль добавят закрытые сведения компании.

**Балл подборки** (те же 732 закупки прошлого, профиль из 292 контрактов). Тот же балл, что стоит у
закупок в подборке, посчитан для прошлых закупок: он ставит выигранную компанией закупку выше чужой в
72% пар (интервал 66–76%), а среди 73 закупок с самым высоким баллом выигранных 73% при 28% в среднем.
Это показывает, что балл находит закупки, похожие на дело компании. Победу он не предсказывает: чужие
закупки этих заказчиков в основном не из области компании и отличаются по названию. Точную оценку даёт
карточка закупки после чтения документации.

**Чтение документации** (три закупки, модель `openai/gpt-oss-120b`):

| Закупка | Объём | Требований в карточке | Отброшено выводов | Время первого анализа |
|---|---|---|---|---|
| Фиксация нарушений ПДД, 2,99 млрд руб. | 22 части | 76 | 21 из 133 | 9 минут |
| Доступ в Интернет, 12,7 млн руб. | 15 частей | 23 | 17 | 8,5 минуты |
| Доступ в Интернет, 2,9 млн руб. | 7 частей | 29 | 12 | 3,5 минуты |

Почти всё время уходит на ожидание минутного предела модели. Повторная сборка карточки из сохранённых
ответов занимает около минуты, если входные данные не менялись; если изменился профиль компании или
история заказчика, ответы модели на этапе сопоставления запрашиваются заново (около двух запросов).

## Ограничения

- **Проигранных заявок в открытых данных нет.** Участники в протоколах не названы, поэтому
  «чужая закупка» в проверке означает только, что её выиграла не компания. Оценка шансов
  не является статистической вероятностью.
- **Правила пока не откалиброваны и среди похожих закупок не проходят проверку** (см. выше). Одну из
  трёх разобранных закупок компания выиграла, а оценка была «низкий»: код ОКПД2 не совпал с её
  прежними контрактами, а прошлые похожие закупки заказчика выигрывал другой поставщик. Из 23
  выигранных закупок с оценкой «низкий» 17 это работы вне связи (ремонт дорог, поставка оборудования,
  видеоаналитика): открытый профиль их не предвидит.
- **Профиль будет пополняться закрытыми сведениями компании** (другие направления, лицензии,
  персонал, оборудование, опыт). После этого проверку нужно запустить заново, а числа сравнивать с
  оговоркой: в файле проверки записан отпечаток профиля. Все веса и пороги правил собраны в одном
  наборе параметров (`RuleSet`), и `POST /api/backtest/compare` сравнивает несколько наборов на одних
  и тех же сохранённых данных, не обращаясь к API закупок.
- **Фактор «компания уже выигрывала у заказчика» не проверен:** заказчики для проверки взяты
  из числа знакомых, и на такой выборке фактор показывает обратное.
- **Соответствие требованиям не проверяется.** Карточка говорит, что нужно проверить, но не
  говорит, проходит ли компания.
- **Маржа не считается,** пока человек не задаст себестоимость: в открытых данных её нет.
- **Только 44-ФЗ.** Профиль и история заказчика строятся по контрактам 44-ФЗ; анализ проверен
  только на закупках по этому закону.
- **Форматы.** Читаются Word (.docx), простой текст и архивы zip с файлами Word. PDF, старый
  Word (.doc), Excel, RAR и сканы не читаются; такие файлы перечислены в карточке.
- **Техническое задание модель не читает:** оно описывает предмет закупки, а не требования
  к участнику.
- **Подборка предварительная.** В результатах поиска нет кода ОКПД2, поэтому балл строится по словам
  названия, опыту у заказчика и размеру. Ищутся закупки за последние 30 дней, до 10 слов за запуск,
  первая страница каждого поиска; в подборке 20 закупок. Бесплатного источника закупок нет (FTP единой
  информационной системы закрыт, новый сервис требует токен), поэтому один запуск тратит до 10 запросов.
- **Квота источника данных.** На бесплатном тарифе API доступно 100 запросов на метод в год;
  программа останавливается на 90. Один анализ закупки стоит до 7 запросов, одна подборка до 10. Все ответы
  сохраняются на диск и повторно не запрашиваются.

## Запуск

Нужен Python 3.12.

Windows:

    py -3.12 -m venv .venv
    .venv\Scripts\pip install -r requirements.txt
    copy .env.example .env
    .venv\Scripts\python -m app.main

Linux и macOS:

    python3.12 -m venv .venv
    .venv/bin/pip install -r requirements.txt
    cp .env.example .env
    .venv/bin/python -m app.main

В файл `.env` впишите ключи:

| Настройка | Что это |
|---|---|
| `DAMIA_KEY` | ключ сервиса «API-Закупки» (damia.ru) |
| `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` | языковая модель с интерфейсом OpenAI, например Groq: `https://api.groq.com/openai/v1` |
| `LLM_REASONING_EFFORT` | необязательно: `low`, `medium` или `high` для рассуждающих моделей |
| `COMPANY_INN` | необязательно: ИНН компании; по умолчанию 7713076301 |

Сервер слушает только `127.0.0.1:8765`. После запуска откройте http://localhost:8765: сервер сам
отдаёт ту же страницу, что и на GitHub Pages, но с действиями (описание ниже). Все запросы
доступны и напрямую: страница документации API http://localhost:8765/docs (у каждого запроса
там есть форма для вызова) или любой HTTP-клиент.

Тесты:

    .venv\Scripts\python -m unittest discover -s tests -t .

## Локальный интерфейс

Страница на http://localhost:8765 определяет, что открыта с этого компьютера, читает данные прямо
с сервера и показывает раздел «Управление»:

- состояние ключей и модели, остаток квоты DaMIA по методам;
- «Построить профиль» компании;
- «Построить подборку»: программа сама ищет по словам из профиля и оставляет лучшие закупки с
  баллом и причинами; перед запуском называет цену в запросах (до 10 запросов `zsearch`);
- «Найти закупки»: запрос и дата начала, список обновляется на странице;
- «Анализировать» у любой закупки в списке или по номеру закупки: ход задачи виден на странице
  (шаг, сколько сделано, сколько прошло), готовая карточка открывается сама. Если страницу закрыть,
  анализ продолжится на сервере, а после повторного открытия ход покажется снова.

Каждое действие, которое тратит запросы к DaMIA, скачивает файлы или обращается к модели, сначала
называет цену и ждёт подтверждения кнопкой. Одновременно идёт один анализ. Изменяющие запросы
принимаются только с этого компьютера. На GitHub Pages та же страница работает без действий.

## Порядок работы (запросы API)

Запросы, которые тратят квоту или скачивают файлы, требуют явного разрешения в теле запроса
(`network`, `download`); без него программа работает только с сохранёнными ответами.

| Шаг | Запрос |
|---|---|
| Построить профиль | `POST /api/profile/build` `{"network": true, "max_pages": 3}` |
| Найти закупки | `POST /api/tenders/search` `{"query": "услуги связи", "from_date": "2026-11-01", "network": true}` |
| Узнать цену подборки в запросах | `GET /api/shortlist/plan` |
| Построить подборку лучших закупок | `POST /api/shortlist/run` `{"network": true, "queries": 10}` |
| Посмотреть последнюю подборку | `GET /api/shortlist` |
| Посмотреть файлы закупки | `GET /api/tenders/{номер}/documents` |
| Запустить анализ | `POST /api/tenders/{номер}/analyze` `{"network": true, "download": true}` |
| Следить за ходом | `GET /api/jobs/{id}` |
| Получить карточку | `GET /api/cards/{номер}` |
| Проверить правила на прошлых закупках | `POST /api/backtest/run` `{"network": true}` |
| Собрать пакет файлов для показа без сервера | `POST /api/export` |
| Сравнить наборы правил на сохранённых данных | `POST /api/backtest/compare` `{"variants": {"имя": {"wins_none": 0}}}` |
| Узнать остаток квоты | `GET /api/quota` |
| Что сейчас лежит в результатах | `GET /api/index` |
| Последние задачи анализа | `GET /api/jobs` |

Результаты лежат в папке `data/out`, пакет для показа в `data/export`. Папка `data` в репозиторий
не входит: в ней ответы API и скачанные документы.

## Веб-страница

Страница лежит в папке `docs`: обычные HTML, CSS и JavaScript без сборки, GitHub Pages публикует
папку как есть. Данные страницы в `docs/data` это копия пакета из `data/export`. Чтобы обновить
страницу, соберите пакет и замените папку:

    curl -X POST http://localhost:8765/api/export
    rmdir /s /q docs\data && xcopy /e /i data\export docs\data

Открыть страницу как на GitHub Pages, без сервера приложения:
`python -m http.server 8770 --bind 127.0.0.1` в папке `docs`, затем http://localhost:8770.
Открытая как файл с диска, страница данные не загрузит. Страница, которую отдаёт сервер
приложения на 8765, читает данные не из `docs/data`, а с сервера.

| `app/sources` | источники: API закупок с кэшем и счётчиком квоты, скачивание документов, извлечение текста, языковая модель |

## Безопасность

- **Ключи** читаются только из `.env` или переменных окружения. Они не попадают в ответы, журналы,
  сохранённые ответы API и пакет для показа; пакет не собирается, если в любом его файле встретилось
  значение ключа. `.env`, сырые ответы API, скачанные документы и ответы модели в git не входят.
- **Локальный сервер** слушает только `127.0.0.1`. Он отвечает лишь на запросы, адресованные этому
  компьютеру (заголовок Host `localhost`, `127.0.0.1` или `[::1]`): это защищает от подмены адреса через
  DNS, когда чужой сайт пытается читать результаты с вашего компьютера. Запросы, которые что-то
  меняют, тратят квоту или обращаются к модели, дополнительно принимаются только с этого компьютера и
  только со страницы, открытой с него же; всё остальное получает отказ.
- **Страница не встраивается** в чужие страницы (заголовки `X-Frame-Options` и `frame-ancestors`), чтобы
  чужой сайт не мог подсунуть кнопку подтверждения под свой рисунок. Браузер не угадывает тип содержимого.
- **Исходящие запросы** к API закупок и к модели не следуют перенаправлениям: ключ стоит в адресе или
  в заголовке и не должен уйти на другой адрес. Размер ответа ограничен (30 МБ и 5 МБ).
- **Файлы** скачиваются только с zakupki.gov.ru по https; каждое перенаправление проверяется, размер
  файла ограничен 30 МБ. Архив zip читается не больше 20 файлов и 100 МБ, XML с объявлениями
  сущностей отвергается.
- **Чужой текст** (документация, цитаты, названия) вставляется на страницу только как текст, не как
  разметка. Политика безопасности страницы запрещает встроенные скрипты и стили. Ссылки из данных
  открываются, только если это адрес https.
- **Текст документации для модели** это данные, а не команды: у модели нет инструментов, а каждый её
  вывод показывается, только если цитата найдена в документе. Подложенная в документ инструкция может
  исказить формулировку вывода, но не заставит программу что-то выполнить.

Ключи лежат в файле `.env` на вашем компьютере: файл не должен уходить вместе с папкой проекта
(архив, облачная синхронизация, показ экрана). Если ключ засветился, достаточно перевыпустить его у
поставщика. В истории git виден адрес почты автора коммитов.
